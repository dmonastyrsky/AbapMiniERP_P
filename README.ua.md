## 1. Огляд проєкту

Mini ERP — це демонстраційна ERP-система, розроблена за допомогою моделі програмування SAP ABAP Cloud та SAP RESTful Application Programming Model (RAP) в середовищі SAP BTP ABAP Environment.

Проєкт реалізує спрощену доменну модель закупівель, складського обліку та продажів, дотримуючись сучасних практик розробки SAP. Сюди входять принципи SAP Clean Core (чисте ядро), бізнес-об'єкти RAP Business Objects, ракурси CDS View Entities, сервіси OData V4 та SAP Fiori Elements.

Застосунок є портфоліо-проєктом, що демонструє готову до хмари (cloud-ready) розробку на ABAP, суворе розділення шарів архітектури та корпоративні шаблони проєктування.

Детальна технічна архітектура та специфікації доменної моделі доступні в [Архітектура та технічний дизайн](docs/Architecture.ua.md).

## 2. Технологічний стек

- **Платформа:** SAP BTP ABAP Environment
- **IDE:** Eclipse ADT (ABAP Development Tools)
- **Модель програмування:** SAP RESTful Application Programming Model (RAP)
- **Моделювання даних:** ABAP Core Data Services / CDS View Entities
- **Персистентність:** Transparent Tables з підтримкою RAP Draft (Чернеток RAP)
- **Сервіси:** OData V4 UI Services (`ZUI_MERP_O4`, `ZUI_MERP_PROCUREMENT_O4`)
- **UI-фреймворк:** SAP Fiori Elements
- **Стандарт розробки:** SAP Clean Core / ABAP Cloud

## 3. Статус реалізації та план робіт

Проєкт структуровано на два основних етапи.

### Етап 1: Управління основними даними (Master Data Management) — Завершено
- **Company Code (Організація):** Операційні організації з налаштуваннями країни та валюти (ручне присвоєння ключів).
- **Warehouse (Склад):** Фізичні місця зберігання, закріплені за конкретною організацією (автоматичне присвоєння ключів).
- **Business Partner (Бізнес-партнер):** Клієнти, постачальники або контрагенти, що поєднують обидві ролі (автоматичне присвоєння ключів).
- **Item Group (Групи товарів):** Класифікація продуктів із базовою ставкою ПДВ для автоматичного успадкування (автоматичне присвоєння ключів).
- **Item (Товари/Послуги):** Матеріальні продукти та нематеріальні послуги (автоматичне присвоєння ключів).
- **VAT Rate (Ставки ПДВ):** Центральний механізм для конфігурації та ведення податкових ставок (автоматичне присвоєння ключів).

### Етап 2: Transactional Engine & Inventory (Транзакційне ядро та складський облік) — У процесі розробки

#### Procurement (Закупівлі)
- **Purchase Orders (Замовлення на закупівлю) — Реалізовано:** Повний життєвий цикл закупівельного документа (Новий, Затверджений, В доставці, Завершений, Скасований) з нумерацією документів у розрізі компаній, інтерактивною обробкою помилок у реальному часі, перевіркою дублів позицій та автоматичним розрахунком сум у позиціях і заголовку.
- **Goods Receipts (Надходження матеріалів) — Заплановано:** Майбутня реалізація для проведення часткових та повних складських надходжень за замовленнями.

#### Sales (Продажі)
- **Sales Orders (Замовлення на продаж) — Заплановано:** Майбутня реалізація життєвого циклу документів продажів покупцям.
- **Goods Issues (Відпуск матеріалів) — Заплановано:** Майбутня реалізація для проведення складського відпуску та відвантаження товарів.

#### Dynamic Stock Calculation (Динамічний розрахунок запасів) — Заплановано
- Динамічний розрахунок залишків на складах у реальному часі (`Запаси = Надходження - Відпуск`) за допомогою CDS View Entities після реалізації документів надходження та відпуску.

## 4. Ключові архітектурні особливості

### Гібридний механізм діапазонів номерів (`ZCL_MERP_NUM_RANGE_UTIL`)
- **Первинний розподіл ключів:** Стандартний SAP Number Range Object (NRO) API через `cl_numberrange_runtime`.
- **Резервний варіант DB Max:** Динамічний пошук через Open SQL, який сканує як активні таблиці, так і таблиці чернеток (`nmax`), для запобігання колізій ключів під час паралельних сесій користувачів із чернетками.
- **Синхронізація NRO:** Автоматичне вирівнювання інтервалів через `cl_numberrange_intervals` після виконання початкового завантаження даних (seed).

### Автоматичне успадкування податків та значень (`ZCL_MERP_MD_UTIL`)
- **Ієрархічне визначення ПДВ:** Код ПДВ для Item успадковується за ланцюжком: `Item Master` -> `Item Group Default` -> `Manual Fallback`.

### Реляційна цілісність та перевірки використання
- **Шаблон масової перевірки (Bulk Precheck):** Реалізований у хендлерах поведінки RAP (`precheck_delete`) для всіх сутностей Master Data для запобігання видаленню записів, що використовуються.
- **Оптимізація масових SQL-запитів:** Сканує спеціалізовані CDS Usage Views (`ZMERP_I_<ENTITY>_USAGE`) з дедуплікованими наборами ключів для усунення накладних витрат $N+1$ запитів.

### Управління операційним статусом
- **М'яке блокування (Soft Blocking):** Записи Master Data використовують прапорець `IsBlocked` для збереження цілісності історичних даних замість фізичного видалення.
- **Фільтрація у Value Help:** Усі операційні ракурси підказки вводу (`ZMERP_I_<ENTITY>_VH`) застосовують умову `WHERE IsBlocked = ''` для запобігання вибору неактивних записів у нових документах.

### Ядро замовлень на закупівлю та автоматичні розрахунки
- **Ядро розрахунку документів (`ZCL_MERP_DOC_CALC`):** Автоматичний розрахунок фінансових сум позицій у реальному часі (Нетто, ПДВ, Брутто) при зміні кількості, ціни або ставки податку, а також миттєва агрегація загальних сум документа на рівні заголовка.
- **Інтерактивна обробка помилок:** Миттєве очищення та підсвічування повідомлень валідації безпосередньо під час введення чи виправлення полів користувачем.
- **Запобігання дублюванню:** Автоматичне виявлення та блокування повторного введення однакових позицій товарів у межах одного документа.

### Автоматичне початкове налаштування (`ZCL_MERP_INITIAL_SETUP`)
- Запускний клас консолі, що реалізує інтерфейс `IF_OO_ADT_CLASSRUN`.
- Наповнює початковими тестовими даними всі сутності Master Data.
- Очищає як Active, так і RAP Draft таблиці під час ініціалізації.
- Автоматично синхронізує рівні послідовності NRO для відображення завантажених записів.

## 5. Service Bindings & UI Preview

Застосунок відкриває розділені OData V4 сервіси для використання у SAP Fiori Elements:
- **Сервіс Основних даних (`ZUI_MERP_O4`):** Відкриває всі сутності Master Data (Організація, Склад, Бізнес-партнер, Групи товарів, Товари/Послуги, Ставки ПДВ).
- **Сервіс Закупівель (`ZUI_MERP_PROCUREMENT_O4`):** Відкриває транзакційні сутності Закупівель (Заголовки та позиції замовлень на закупівлю).

---

## 6. Принципи Clean Core

- **Суворий обсяг ABAP Cloud:** Нульове використання застарілих інструкцій ABAP або невипущених стандартних API від SAP.
- **Можливості RAP Draft:** Вбудована обробка станів для транзакційної безстатусної HTTP-комунікації.
- **Автоматичний аудит:** Уніфіковане заповнення полів аудиту (`CREATED_BY`, `CREATED_AT`, `LAST_CHANGED_AT` тощо).

---

## 7. Налаштування та запуск

1. Імпортуйте репозиторій у ваше середовище SAP BTP ABAP Environment за допомогою інструменту **abapGit** в Eclipse ADT.
2. Активуйте CDS View Entities, Behavior Definitions та Service Bindings в ієрархічному порядку.
3. Відкрийте Service Bindings `ZUI_MERP_O4` та `ZUI_MERP_PROCUREMENT_O4` і натисніть **Publish** (або **Unpublish / Publish**) для реєстрації локальних кінцевих точок OData V4.
4. Запустіть клас `ZCL_MERP_INITIAL_SETUP` в Eclipse ADT (`F9`) для заповнення початкових даних та синхронізації діапазонів номерів.
5. Перегляньте роботу застосунків за допомогою Fiori Elements Preview в будь-якому редакторі Service Binding.
