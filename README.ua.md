## 1. Огляд проєкту[cite: 12]

Mini ERP — це демонстраційна ERP-система, розроблена за допомогою моделі програмування SAP ABAP Cloud та SAP RESTful Application Programming Model (RAP) в середовищі SAP BTP ABAP Environment.[cite: 12]

Проєкт реалізує спрощений процес закупівель, складського обліку та продажів, дотримуючись сучасних практик розробки SAP. Сюди входять принципи SAP Clean Core (чисте ядро), бізнес-об'єкти RAP Business Objects, ракурси CDS View Entities, сервіси OData V4 та SAP Fiori Elements.[cite: 12]

Застосунок є портфоліо-проєктом, що демонструє готову до хмари (cloud-ready) розробку на ABAP, суворе розділення шарів архітектури та корпоративні шаблони проєктування.[cite: 12]

Детальна технічна архітектура та специфікації доменної моделі доступні в [Архітектура та технічний дизайн](docs/Architecture.ua.md).[cite: 7, 11, 12]

## 2. Технологічний стек[cite: 12]

- **Платформа:** SAP BTP ABAP Environment[cite: 12]
- **IDE:** Eclipse ADT (ABAP Development Tools)[cite: 12]
- **Модель програмування:** SAP RESTful Application Programming Model (RAP)[cite: 12]
- **Моделювання даних:** ABAP Core Data Services / CDS View Entities[cite: 12]
- **Персистентність:** Transparent Tables з підтримкою RAP Draft (Чернеток RAP)[cite: 12]
- **Сервіси:** OData V4 UI Services[cite: 12]
- **UI-фреймворк:** SAP Fiori Elements[cite: 12]
- **Стандарт розробки:** SAP Clean Core / ABAP Cloud[cite: 12]

## 3. Статус реалізації та план робіт[cite: 12]

Проєкт структуровано на два основних етапи.[cite: 12]

### Етап 1: Управління основними даними (Master Data Management) — Завершено[cite: 12]
- **Company Code (Організація):** Операційні організації з налаштуваннями країни та валюти (ручне присвоєння ключів).[cite: 12]
- **Warehouse (Склад):** Фізичні місця зберігання, закріплені за конкретною організацією (автоматичне присвоєння ключів).[cite: 12]
- **Business Partner (Бізнес-партнер):** Клієнти, постачальники або контрагенти, що поєднують обидві ролі (автоматичне присвоєння ключів).[cite: 12]
- **Item Group (Групи товарів):** Класифікація продуктів із базовою ставкою ПДВ для автоматичного успадкування (автоматичне присвоєння ключів).[cite: 12]
- **Item (Товари/Послуги):** Матеріальні продукти та нематеріальні послуги (автоматичне присвоєння ключів).[cite: 12]
- **VAT Rate (Ставки ПДВ):** Центральний механізм для конфігурації та ведення податкових ставок (автоматичне присвоєння ключів).[cite: 12]

### Етап 2: Transactional Engine & Inventory (Транзакційне ядро та складський облік) — У процесі розробки[cite: 12]
- **Purchase Orders (Замовлення на закупівлю) — Завершено:** Повний життєвий цикл закупівельного документа (Новий, Затверджений, В доставці, Завершений, Скасований) з нумерацією документів у розрізі компаній, автоматичним розрахунком сум у позиціях і загальних сум документа, перевіркою дублів позицій та інтерактивними валідаціями в реальному часі.[cite: 7, 12]
- **Goods Receipts & Sales Engine:** Часткові надходження, замовлення на продаж та відпуск матеріалів.[cite: 12]
- **Dynamic Stock Calculation (Динамічний розрахунок запасів):** Розрахунок інвентарю в реальному часі (`Запаси = Надходження - Відпуск`), який обчислюється динамічно за допомогою CDS View Entities без використання постійних таблиць запасів.[cite: 12]

## 4. Ключові архітектурні особливості[cite: 12]

### Гібридний механізм діапазонів номерів (`ZCL_MERP_NUM_RANGE_UTIL`)[cite: 12]
- **Первинний розподіл ключів:** Стандартний SAP Number Range Object (NRO) API через `cl_numberrange_runtime`.[cite: 12]
- **Резервний варіант DB Max:** Динамічний пошук через Open SQL, який сканує як активні таблиці, так і таблиці чернеток (`nmax`), для запобігання колізій ключів під час паралельних сесій користувачів із чернетками.[cite: 12]
- **Синхронізація NRO:** Автоматичне вирівнювання інтервалів через `cl_numberrange_intervals` після виконання початкового завантаження данных (seed).[cite: 12]

### Автоматичне успадкування податків та значень (`ZCL_MERP_MD_UTIL`)[cite: 12]
- **Ієрархічне визначення ПДВ:** Код ПДВ для Item успадковується за ланцюжком: `Item Master` -> `Item Group Default` -> `Manual Fallback`.[cite: 12]

### Реляційна цілісність та перевірки використання[cite: 12]
- **Шаблон масової перевірки (Bulk Precheck):** Реалізований у хендлерах поведінки RAP (`precheck_delete`) для всіх сутностей Master Data для запобігання видаленню записів, що використовуються.[cite: 12]
- **Оптимізація масових SQL-запитів:** Сканує спеціалізовані CDS Usage Views (`ZMERP_I_<ENTITY>_USAGE`) з дедуплікованими наборами ключів для усунення накладних витрат $N+1$ запитів.[cite: 12]

### Управління операційним статусом[cite: 12]
- **М'яке блокування (Soft Blocking):** Записи Master Data використовують прапорець `IsBlocked` для збереження цілісності історичних даних замість фізичного видалення.[cite: 12]
- **Фільтрація у Value Help:** Усі операційні ракурси підказки вводу (`ZMERP_I_<ENTITY>_VH`) застосовують умову `WHERE IsBlocked = ''` для запобігання вибору неактивних записів у нових документах.[cite: 12]

### Автоматизовані розрахунки та валідація в реальному часі[cite: 7, 12]
- **Ядро розрахунку документів:** Автоматичний розрахунок фінансових сум позицій у реальному часі при зміні кількості, ціни або ставки податку, а також миттєва агрегація загальних сум документа на рівні заголовка.[cite: 7, 12]
- **Інтерактивна обробка помилок:** Миттєве очищення та підсвічування повідомлень валідації безпосередньо під час заповнення чи виправлення полів користувачем.[cite: 7, 12]
- **Запобігання дублюванню:** Автоматичне виявлення та блокування повторного введення однакових позицій товарів у межах одного документа.[cite: 7, 12]

### Автоматичне початкове налаштування (`ZCL_MERP_INITIAL_SETUP`)[cite: 12]
- Запускний клас консолі, що реалізує інтерфейс `IF_OO_ADT_CLASSRUN`.[cite: 12]
- Наповнює початковими тестовими даними всі сутності Master Data.[cite: 12]
- Очищає як Active, так і RAP Draft таблиці під час ініціалізації.[cite: 12]
- Автоматично синхронізує рівні послідовності NRO для відображення завантажених записів.[cite: 12]

## 6. Принципи Clean Core[cite: 12]

- **Суворий обсяг ABAP Cloud:** Нульове використання застарілих інструкцій ABAP або невипущених стандартних API від SAP.[cite: 12]
- **Можливості RAP Draft:** Вбудована обробка станів для транзакційної безстатусної HTTP-комунікації.[cite: 12]
- **Автоматичний аудит:** Уніфіковане заповнення полів аудиту (`CREATED_BY`, `CREATED_AT`, `LAST_CHANGED_AT` тощо).[cite: 12]

---

## 7. Налаштування та запуск[cite: 12]

1. Імпортуйте репозиторій у ваше середовище SAP BTP ABAP Environment за допомогою інструменту **abapGit** в Eclipse ADT.[cite: 12]
2. Активуйте CDS View Entities, Behavior Definitions та Service Bindings в ієрархічному порядку.[cite: 12]
3. Відкрийте Service Binding `ZUI_MERP_O4` і натисніть **Publish** (або **Unpublish / Publish**) для реєстрації локальної кінцевої точки OData V4.[cite: 12]
4. Запустіть клас `ZCL_MERP_INITIAL_SETUP` в Eclipse ADT (`F9`) для заповнення початкових даних та синхронізації діапазонів номерів.[cite: 12]
5. Перегляньте роботу застосунків за допомогою Fiori Elements Preview в редакторі Service Binding.[cite: 12]
