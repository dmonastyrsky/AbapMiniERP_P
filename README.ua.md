## 1. Огляд проєкту

Mini ERP — демонстраційна ERP-система на SAP ABAP Cloud і SAP RESTful Application Programming Model (RAP, managed із чернетками) у SAP BTP ABAP Environment (trial).

Вона охоплює спрощений, але повний бізнес-ланцюжок: основні дані → закупівлі (замовлення на закупівлю → надходження) → склад → продажі (замовлення на продаж → відпуск). Поведінка максимально наближена до стандарту SAP (закупівлі, збут, управління запасами), у спрощеному вигляді.

Це портфоліо-проєкт, що показує cloud-ready розробку на ABAP: бізнес-об'єкти RAP, CDS View Entities, сервіси OData V4 і SAP Fiori elements.

Деталі: [Архітектура та технічний дизайн](docs/Architecture.ua.md).

## 2. Технологічний стек

- **Платформа:** SAP BTP ABAP Environment (trial)
- **IDE:** Eclipse ADT (ABAP Development Tools)
- **Модель програмування:** SAP RAP, managed бізнес-об'єкти з чернетками, strict mode
- **Моделювання даних:** CDS View Entities
- **Зберігання:** таблиці бази даних із таблицями чернеток RAP
- **Сервіси:** OData V4 UI (`ZUI_MERP_O4`, `ZUI_MERP_PROCUREMENT_O4`, `ZUI_MERP_SALES_O4`, `ZUI_MERP_STOCK_O4`)
- **UI:** SAP Fiori elements
- **Стандарт розробки:** ABAP Cloud / Clean Core

|---|---|---|
| Основні дані | Компанія, склад, бізнес-партнер, група товарів, товар/послуга, ставка ПДВ | Реалізовано |
| Закупівлі | Замовлення на закупівлю, надходження | Реалізовано |
| Склад | Журнал рухів і залишки, перевірка наявності, ковзна середня собівартість, блокування запасів, застосунок залишків (лише перегляд) | Реалізовано |
| Продажі | Замовлення на продаж, відпуск | Реалізовано |

**Ідеї, не розпочато:** переміщення між складами (як вид руху SAP 311); автоматична пропозиція ціни в документах.
**Відкладено:** перерахунок валют; закриття окремого рядка замовлення; залишки на дату / закриття періоду.

## 4. Ключові можливості

### Нумерація
- Коди основних даних беруться з об'єктів діапазонів номерів під час створення (`WH001`, `V001`, `00001`); код компанії вводиться вручну.
- Номери документів ведуться окремо за типом документа і компанією, з префіксом компанії (`DE00000001`), і присвоюються під час першого збереження. Чернетки номера не мають.
- Без резервного варіанта: якщо діапазон номерів не спрацював, нічого не зберігається (давніший резервний варіант через максимум у базі давав дублі номерів і був прибраний).
- Нова компанія автоматично отримує інтервали для всіх типів документів.

### Цілісність основних даних
- Запис, який десь використовується, не можна видалити; повідомлення називає кожен об'єкт, що його використовує.
- Критичні поля стають лише для читання, щойно запис використано в документах (наприклад, валюта і префікс компанії, компанія складу, тип і базова одиниця товару, відсоток ПДВ, роль партнера, що використовується).
- Блокування замість видалення: заблоковані записи приховані в підказках вводу і не пропонуються за замовчуванням; наявні документи з ними лишаються чинними, їх можна редагувати і проводити.
- Основні дані SAP (валюта, країна, одиниця виміру) перевіряються і в підказці вводу, і на бекенді.

### Документи
- Суми рядків (нетто, ПДВ, брутто) і підсумки заголовка перераховуються при кожній зміні; ціни без ПДВ.
- Повідомлення перевірки поля зникають, щойно поле виправлено; дублі товарів відхиляються.
- До появи перерахунку валют дозволена лише валюта компанії; дата проведення не може бути в майбутньому.

### Замовлення → наступний документ
- Надходження / відпуск створюється або із замовлення (дія «Goods Receipt» / «Goods Issue», як SAP «створення з посиланням»), або вибором замовлення в самому документі.
- Рядки заповнюються відкритими кількостями; якщо береться вся відкрита кількість, беруться й відкриті суми, тож останнє надходження / відпуск точно закриває копійки.
- Без перевищення замовленої кількості; статус замовлення (у доставці / в обробці / завершено) змінюється автоматично за проведеними документами.

### Склад
- Рухи запасів записуються на етапі збереження проведення; залишки рахуються з журналу.
- Надходження збільшує запас на свою суму нетто; відпуск оцінюється за ковзною середньою собівартістю, як у SAP.
- Відпуск проводиться лише за наявності запасу; скасування проведення надходження не може зробити залишок від'ємним.
- Проведення і скасування проведення блокують замовлення і запаси його товарів, тож паралельні проведення не можуть списати зайве.
- Послуги не створюють рухів запасів.

### Тестові дані
- `ZCL_MERP_INITIAL_SETUP` (запуск F9) очищає всі дані і створює основні дані та документи закупівель і продажів у всіх статусах, включно з випадками округлення та ковзної середньої.

## 5. Сервіси та перегляд UI

Один сервіс OData V4 на область:
- **Основні дані (`ZUI_MERP_O4`):** компанія, склад, бізнес-партнер, група товарів, товар/послуга, ставка ПДВ.
- **Закупівлі (`ZUI_MERP_PROCUREMENT_O4`):** замовлення на закупівлю, надходження та їхні рядки (плюс основні дані, на які вони посилаються). Опубліковано також через communication scenario.
- **Продажі (`ZUI_MERP_SALES_O4`):** замовлення на продаж, відпуски та їхні рядки (плюс основні дані, на які вони посилаються).
- **Склад (`ZUI_MERP_STOCK_O4`):** залишки і рухи запасів, лише перегляд.

## 6. Принципи Clean Core

- **Строгий ABAP Cloud:** лише випущені (released) API та об'єкти SAP.
- **Чернетки RAP:** вбудоване керування станом для HTTP-комунікації без стану; стандартні блокування чернеток.
- **Адміністративні дані:** `CREATED_BY`, `CREATED_AT`, `LOCAL_LAST_CHANGED_BY`, `LOCAL_LAST_CHANGED_AT`, `LAST_CHANGED_AT` заповнює фреймворк для всіх записів; вони ж забезпечують оптимістичне блокування (ETag).

## 7. Встановлення та запуск

1. Імпортуйте репозиторій у SAP BTP ABAP Environment через **abapGit** в Eclipse ADT.
2. Активуйте об'єкти (словник, CDS-ракурси, behavior definitions, сервіси).
3. Відкрийте service bindings `ZUI_MERP_O4`, `ZUI_MERP_PROCUREMENT_O4`, `ZUI_MERP_SALES_O4`, `ZUI_MERP_STOCK_O4` і натисніть **Publish** (або **Unpublish / Publish**).
4. Запустіть клас `ZCL_MERP_INITIAL_SETUP` в Eclipse ADT (`F9`): він очищає всі дані і створює основні дані та документи. Можна запускати повторно будь-коли, щоб скинути систему.
5. Відкрийте застосунки через Fiori elements preview у редакторах service binding. Демо-компанія: **3000**.
